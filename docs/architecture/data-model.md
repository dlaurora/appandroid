# Data Model

## Client

Phase 2 stores one `Client` model.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `id` | `String` | Yes | Stable UUID generated by the app; never derived from user data |
| `fullName` | `String` | Conditional | Required when `businessName` is blank |
| `businessName` | `String` | Conditional | Required when `fullName` is blank |
| `phone` | `String` | No | Flexible phone text, length-limited |
| `email` | `String` | No | Optional; validated only when present |
| `address` | `String` | No | App-private storage only |
| `notes` | `String` | No | App-private storage only |
| `createdAt` | `Long` | Yes | Epoch milliseconds; immutable after creation |
| `updatedAt` | `Long` | Yes | Epoch milliseconds; changes only on real edits |
| `isArchived` | `Boolean` | Yes | Logical archive; no physical delete in Phase 2 |

## Storage

Room table: `clients`.

Indexes:

- `id` primary key.
- `isArchived` for active/archived lists.
- normalized search columns for name, business, phone, and email.

Normalized columns are for search and duplicate detection only. The UI shows the user's stored display values.

## Domain And UI Separation

- `ClientEntity`: Room persistence representation.
- `Client`: domain representation used by use cases.
- `ClientUiModel` and form state: display and editable UI representation.

Mappers are explicit and tested. UI code does not depend directly on Room entities.

## Backup Decision

Client records are personal data. Phase 2 excludes the Room database from Android Auto Backup and cloud/device-transfer data extraction rules until a dedicated backup/import phase defines user control, disclosure, validation, and recovery behavior.
